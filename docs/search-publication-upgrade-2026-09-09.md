# 数据库、发布与搜索升级

SQLite 构建先完整验证源数据，再在同目录临时数据库构建。文件解析、哈希或插入失败立即中止；验证数据库完整性、FTS 一致性和条数，并确认索引代次未变化后，原子替换目标。旧数据库在失败时保留。`--data-dir` 未搭配 `--output` 时，数据库写入指定数据目录。

索引包含每个文档内容哈希；SQLite 保存三个索引文件的 SHA256 摘要及构建完成标记。查询核对摘要，拒绝旧代数据库，不依赖文件修改时间。数据目录视为已发布快照：正文编辑必须重新生成索引，再构建 SQLite；不要绕过维护工具直接改在线文件。

搜索使用 FTS5 区分大小写的 trigram 候选索引，再用 `instr` 精确过滤，保留中文子串、标点、大小写语义。1–2 字及含 NUL 查询走扫描；旧 SQLite 不支持 trigram 时构建报错并保留旧库。数据库缺失、旧代或不可读时回退 JSON。JSON 回退不是高吞吐方案。

```bash
python3 scripts/build_sqlite.py --data-dir data --verify
python3 scripts/benchmark_search.py --data-dir data --output benchmark.json
```

发布要求暂停服务。`promote_recovery.py` 预先验证恢复报告，把原报告备份、目录切换、新报告及发布回执纳入同一个异常回滚范围。写报告或回执失败时恢复旧目录及旧报告，回滚报告使用文件替换，避免再次分配空间。成功备份包含旧报告。此流程处理可捕获异常，不承诺掉电/强制终止后的自动事务恢复。

2026-09-09 本机同库三次测量：无匹配长词中位延迟 334→13 ms，“违约责任”341→16 ms；“合同”仍扫描，约 487 ms。所有采样结果与精确 SQL 扫描一致。测量为顺序热缓存采样，不是并发压测。

搜索条号与 JSON 原始条号一致，不使用可能有损的数字别名。两处异常上游编号仍完整保留供核对；数字映射条数不一致的版本禁止作为单条检索证据，HTTP 单条接口返回 409。
