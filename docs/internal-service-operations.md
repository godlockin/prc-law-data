# 内部服务运行与故障处理

当前服务用于受控内部网络。公众入口仍应采用成熟网关、TLS、用户身份、速率限制和租户隔离。

## 启动

在安全环境中配置至少 32 字符的 `PRC_LAW_DATA_TOKEN`，不放入命令行参数或代码。客户端使用相同变量。服务本身不提供 TLS，跨机器部署应通过 TLS 反向代理或受控加密隧道，不能把令牌发到不可信明文网络。

```bash
python3 scripts/serve.py --data-dir data --host 127.0.0.1 --port 8765 --workers 16 --require-db
python3 scripts/readiness_audit.py --data-dir data --output readiness.json
```

服务启动前执行完整数据验证。默认仅回环可无令牌；非回环必须有令牌。CLI 检查不替代防火墙或网络配置。`--require-db` 推荐在持续运行环境使用，数据库不匹配时返回 503，避免悄悄进入昂贵的 JSON 全库扫描。

## 探针和指标

- `/healthz`：无需鉴权，表示进程存活。过载时也可能返回 503。
- `/readyz`：配置令牌时需鉴权，返回数据库就绪和数据代次；不就绪返回 503。
- `/metrics`：配置令牌时需鉴权，返回请求状态计数、总耗时和过载拒绝数。内存指标重启归零，需外部采集才能形成长期指标。
- 日志为每请求 JSON：请求 ID、状态、耗时；不记录查询、令牌、IP。需部署日志轮转/保留策略，避免长期占满磁盘。

401：核对客户端与服务令牌、代理是否保留 Authorization；不要把令牌贴入聊天或日志。503：先看就绪与过载计数；数据代次不一致时验证并重建 SQLite，过载时检查慢查询和容量，不要直接无限增加线程。

## 约束

最大并发处理默认 16、连接超时 10 秒、查询最多 256 字符、offset 最大 10000。线程上限是资源保护，不是按用户限流，也不保证 CPU 查询在 10 秒内中断。大规模导出应另设离线导出任务，不能无限深分页。

更新法律数据应暂停服务，验证并构建新库，再启动；配置 `--require-db`。快照文件、索引和数据库必须属于同一代。就绪检查验证索引/数据库身份，不会在每次探针时重新计算全库正文哈希；持续篡改检测需要定期运行 verify.py。

人工法律复核、官方时效性、私密材料保留及异常资料队列必须另外落实。技术 ready 不表示法律意见可自动发布。
